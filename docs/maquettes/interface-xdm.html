Écran 1 — Téléchargements

La vue par défaut : ce que fait l'outil en continu.

  1. Progression par connexion, pas seulement globale : elle vient de onProgress({done, total}) du moteur, déjà branché.
  2. L'échec est visible et nommé (« 401 »), pas un point rouge muet : le statut HTTP réel remonte du client.
  3. Arrêter déclenche l'arrêt coopératif : les tâches en vol finissent, l'état est sauvegardé, code 130. Une seconde pression quitte tout de suite.
  4. Carte des morceaux : représentation directe de la structure interne (liste d'intervalles). Sert au diagnostic : on voit où ça bloque.
Aucun contrôle de cet écran ne demande de code métier nouveau : tout existe déjà en ligne de commande.

Écran 2 — Aspirer un site

L'assistant, en trois étapes. C'est le cœur du produit.

  1. Dossier proposé automatiquement à partir de l'hôte : une aspiration ne se mélange pas avec une autre.
  2. Profondeur 1 à 5 : la valeur par défaut de la cible (2) est reprise ; le sens de chaque niveau est écrit sous le contrôle.
  3. Filtres en pastilles : l'exclusion des médias lourds reste par défaut, et la règle « l'inclusion l'emporte » est affichée — c'est la source d'erreur n°1 en pratique.
  4. Tester le plan avant de lancer : montre pages, fichiers, cibles et arrêt éventuel, sans créer un dossier ni écrire un octet.
Le panneau d'estimation est calculé par le même code que l'exécution : pas de second algorithme qui divergerait.

Écran 3 — Aspiration en cours

Le suivi : ce qui avance, ce qui a été écarté, et pourquoi.

  1. Arrêter ici aussi : file et projet restent cohérents, « Reprendre » continue exactement où l'on s'est arrêté.
  2. Un échec n'arrête pas l'aspiration ; il est compté à part et rejouable. Le code de sortie dira 1 à la fin, jamais 0.
  3. Journal du parcours : chaque page demandée, chaque rejet avec son motif (robots.txt, hors site, filtre). C'est le diagnostic, pas une décoration.
Les événements arrivent déjà un par un (start, done, failed, retry) : l'interface les affiche sans les réinventer.

Écran 4 — Vérification

« L'aspiration est-elle vraiment sur le disque ? » — sans réseau.

  1. Le code de sortie est affiché, parce qu'il est le contrat pour les scripts : 1 = écart.
  2. Échec ≠ en attente : une tâche tentée et ratée est un écart ; une tâche jamais lancée ne l'est pas. La distinction est visible dans l'interface.
  3. Export vers les quatre formats déjà produits par le moteur (JSON, CSV, Markdown, HTML autonome).
  4. Rien n'est corrigé par la vérification : elle constate. Le bouton qui répare s'appelle « Reprendre » et vit ailleurs.
La vérification ne touche pas au réseau : elle compare la file au disque, point.

Écran 5 — Réglages

Peu d'options, toutes bornées et explicitées.

  1. Bornes affichées sous chaque contrôle (1–128 connexions, 1–10 Mio par morceau) : une valeur hors bornes est refusée avec la valeur reçue, jamais corrigée en silence.
  2. Pas de démarrage automatique proposé, pas de télémétrie : ce sont des choix de conception, pas des oublis.
  3. Zone de notification seulement pendant un transfert.
Ces réglages correspondent aux options de la CLI : une seule source de vérité, deux façades.
